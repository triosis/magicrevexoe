# Option C review-only operational templates

2026-11-11. These .example files are not installed, executable deployment scripts,
production approvals or production-ready service configuration. Do not copy/start
them without the existing independent gates. No credentials/certificates are
provided. All REPLACE_WITH_/REVIEW_REQUIRED values must be resolved privately.

The reviewed topology is one Nginx receiving clients directly, forwarding to one
Node process on127.0.0.1:3001, and MariaDB on127.0.0.1:3306 using verified DNS TLS.
No CDN, load balancer, forwarded-IP trust extension, containers or multiple Node
workers are included. Exact127.0.0.1 (and its mapped IPv4 socket representation)
is the only trusted proxy peer; only hop0 is trusted. Other local users can still
forge proxy requests: a shared/root-compromised VPS is outside this boundary.

Nginx must overwrite XFF with $remote_addr and XFP with https, remove XFH/Forwarded
and alternative forwarding headers, and retain original URI/raw webhook body.
Express defaults to direct mode unless HTTP_PROXY_MODE=single-nginx-loopback is
explicitly selected with HOST=127.0.0.1. It rejects malformed/chained XFF and
unexpected forwarded-host/Forwarded headers. Direct local health probes can omit
all forwarding headers. Never send client headers directly to the trusted Node
port or expose it publicly. Inspect the complete Nginx configuration for inherited
real_ip settings before approval; this snippet cannot establish that absence.

All paths are proposed, not discovered provider paths. Runtime environment can be
read by the same UID/root; file mode does not protect against a compromised API
reading its own credentials. Protect journals, disable environment/SQL/debug dumps,
and redact private data under approved logging/retention rules. Confirm permissions
on parent directories and certificate renewal replacement files, not only leaf files.
